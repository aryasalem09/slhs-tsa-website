## 2024-07-27 - LRU Cache Eviction Bypass in Rate Limiter
**Vulnerability:** The in-memory rate limiter in `src/lib/studio/rate-limit.ts` used a JavaScript `Map` to store login attempts, enforcing eviction when reaching `MAX_TRACKED_KEYS` (4096) by dropping the oldest inserted entry. Because existing active keys were updated in place without re-insertion, a spamming IP's rate limit entry remained the "oldest" and could be evicted prematurely if 4096 other keys were requested, thus bypassing the rate limiter.
**Learning:** In JavaScript, `Map` insertion order is not automatically updated when values are modified. Modifying an existing rate-limit record doesn't make it the "newest" entry without explicitly deleting and re-setting it.
**Prevention:** Implement explicit Least Recently Used (LRU) behavior in custom Map-based tracking code. **Vulnerability:** API endpoints relying on `JSON.parse` to read request bodies did not strictly validate the `Content-Type` header (e.g., `application/json`). This allowed potential attackers to execute Cross-Site Request Forgery (CSRF) attacks using simple HTML forms with `enctype="text/plain"` to submit JSON-formatted payloads, completely bypassing CORS preflight (`OPTIONS`) requirements.
**Learning:** Browser-enforced CORS preflights are only triggered for specific "non-simple" headers like `Content-Type: application/json`. Without strict server-side validation of this header, attackers can bypass CORS restrictions.
**Prevention:** Always explicitly validate that `Content-Type` includes `application/json` before parsing request bodies as JSON on protected API endpoints.
