## 2024-07-25 - Rate Limiting Eviction Bypass Fixed
**Vulnerability:** Attackers could bypass account lockout mechanisms because the rate-limiter Map was using FIFO (First-In, First-Out) eviction strategy. By flooding the application with requests from spoofed IPs or random usernames, an attacker could force active target accounts to be evicted from the tracking map, allowing infinite login attempts.
**Learning:** In Javascript, `Map` iterators yield elements in insertion order. When evicting old elements using `map.keys().next().value`, it removes the oldest inserted element. If an element is updated (via `map.get()` then modification), its insertion order remains unchanged, making it vulnerable to cache flooding eviction.
**Prevention:** To convert a Map into an LRU (Least Recently Used) cache, you must explicitly `delete(key)` and then `set(key, value)` whenever an item is accessed or updated. This moves it to the end of the insertion order and ensures that active entries are not evicted when the map is full.
